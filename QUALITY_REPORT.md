# Universal Document RAG v5.0 — отчёт о проверках

Дата: 10 октября 2026. Прогон на локальном Linux/Python 3.13, без внешних LLM API.

## Фактически проверено

- `python -m pytest -q`: **51 passed**. Тесты используют реальные библиотеки парсинга и SQLite FTS5, FastAPI TestClient и подменяемый LLM.
- Файлы-примеры создаются во время тестов: PDF с текстовым слоем, сгенерированный сканированный PDF с сеткой и Tesseract OCR, DOCX с OMML, XLSX с многострочной таблицей и формулами, CSV/TSV, HTML, PPTX, JSON/JSONL.
- Excel: формула сохраняется как текст, ячейка и реальная строка документируются; поздние строки таблиц продолжают получать заголовки колонок.
- Таблицы: сохранены исходные ячейки и пары `колонка=значение` для поиска; проверяются границы блоков и отсутствие ложного распознавания обычных изображений как таблиц.
- Жизненный цикл базы: новые файлы, изменение файла, удаление одного файла, **удаление последнего файла**, одинаковые имена в разных папках, контроль безопасной загрузки FAISS.
- API: авторизация, ошибки и отказ при отсутствии инфраструктуры, запрос сквозь FastAPI→RAG→реальный SQLite→ответ с тестовой моделью; формальная проверка существования ссылок, отсутствие необоснованных чисел, критичные ограничения безопасности.
- Контрольный инструмент `tools/quality_gate.py` вычисляет Recall@k и MRR@k, возвращает ненулевой код, если порог не выполнен.
- Компиляция `compileall`, сборка двух отдельных дистрибутивов и проверки ZIP/CLI/импорта проводятся отдельно после тестов.

## Демонстрационный retrieval-бенчмарк

Сгенерировано **180 отдельных .md-файлов** в 15 подпапках с уникальными техпараметрами; SQLite-индексатор обработал **180/180 без ошибок**. На **12 простых синтетических вопросах по идентификаторам**: `Recall@5 = 1.00`, `MRR@5 = 1.00` (12/12). Время индексации в одном локальном прогоне около 0.7 сек; эта цифра зависит от аппаратуры, длины файлов и кешей.

**Это не доказательство 100% качества ответов на реальных документах.** Синтетические данные специально просты: здесь нет сложных PDF, нет оценки поискового поиска по смыслу и нет оценки factuality генерации.

## Проверяемые возможности и их границы

| Возможность | Что проверено | Что НЕ установлено |
|---|---|---|
| OCR табличного PDF | Tesseract + OpenCV извлекает ячейки искусственного скана с чёткими линиями | Таблицы без границ, сложная сетка, реальные фотокопии, рукописные формулы |
| Word формулы | OMML дробь, степень, корень структурно извлекаются; XML хранится | Полная интерпретация любой математической нотации, идеальный MathOCR |
| Excel | Формулы, множество строк, координаты и повтор заголовка | Вычисление значений формул и поддержка всех функций Excel |
| Документы | Интеграционные файлы PDF/DOCX/XLSX/CSV/TSV/PPTX/HTML/JSON | Все реальные кодировки, битые и зашифрованные документы |
| Крупная коллекция | Параллельный intake с ограниченной очередью, 180 отдельных документов | Миллионы файлов, гигабайтные PDF и устойчивость под промышленной нагрузкой |
| Генерация | Универсальный промпт и детекторы выдуманных ссылок/цифр | Реальный GigaChat/OpenAI/local model и экспертная оценка точности |
| FAISS | Безопасная политика загрузки, обход в lexical-mode | Создание и поиск на настоящих больших embedding-индексах |
| Развёртывание | Статический Dockerfile/Compose, сборка артефактов | Docker/systemd на реальном сервере, TLS, сетевые интеграции |

## Запуск повторных проверок

```bash
python -m pip install -r requirements-test.txt
# Системный Tesseract + языки eng, rus
python -m pytest -q
python -m compileall -q api src tools
python make_apps.py --zip
```

Для измерения именно **вашего** качества заведите `cases.jsonl` из 100–300 экспертно размеченных вопросов, как описано в `docs/UNIVERSAL_CORPUS.md`:

```bash
python -m tools.quality_gate --output-dir output --cases cases.jsonl --k 5 --min-recall 0.85
```

## Что необходимо перед production

1. Указать API ключ и настроить LLM; провести реальное интеграционное тестирование в защищённой среде.
2. Измерить WER/CER OCR и cell-exact-match для сканов, формул, нестандартной вёрстки на ваших исходниках.
3. Проверить ответ по фактам, ссылкам и отсутствующим в базе вопросам; отдельно провести стресс-тест и резервное восстановление.
4. Проверить ограничения доступа по документам (ACL пока нет). Не смешивать документы разных уровней допуска в одной общей базе.
5. Проверить пакет и индекс в Docker/systemd на целевом сервере, включая работу FAISS, если он включён.
