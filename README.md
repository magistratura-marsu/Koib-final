# Universal Document RAG v5.0

**Универсальная система поиска и ответов по большой коллекции документов.**
Продолжает поддерживать КОИБ, но больше не ограничивает предметную область:
по умолчанию `RAG_DOMAIN=general`, а специализированный режим можно включить
через `RAG_DOMAIN=koib`.

Это **исходный код**, а не готовая наполненная база. Для осмысленных ответов
нужно проиндексировать свои документы и подключить LLM. Внешние облачные
модели и Docker в офлайн-тестировании этой версии не проверялись.

## Что распознаётся

| Источник | Текст | Таблицы | Формулы / структура | Координаты |
|---|---|---|---|---|
| PDF с текстовым слоем | Да | `PyMuPDF.find_tables` | Текстовые и LaTeX-подобные формулы | Страница, bbox таблицы |
| PDF-скан | Tesseract OCR | OpenCV + Tesseract для **таблиц с нарисованной сеткой** | Выделение формул из OCR-текста, без гарантии сохранения 2D-нотации | Страница, bbox в пикселях |
| DOCX | Да | Таблицы документа | OMML: дроби, индексы, степени, корни (best effort; XML сохранён) | Раздел, порядковый блок (не печатная страница) |
| XLSX / XLSM | Да | Все листы, порции по 75 строк, повтор заголовков | Значения `=...` и адреса формульных ячеек | Лист, фактический номер строки, ячейка |
| CSV / TSV | Да | Авторазделитель, потоковое чтение, сохранение шапки | Текст формул в ячейках | Номера строк |
| HTML | Да | Таблицы с `rowspan` и `colspan` | Текстовые выражения | Заголовок и блок |
| PPTX | Да | Таблицы слайдов | Текст | Номер слайда |
| TXT / MD / RST | Да | Текст | Текстовые формулы | Порядковый блок |
| JSON / JSONL | Да | Пары ключ—значение | Значения полей | Номер записи |

**Важно:** чтение сложных PDF с рукописными формулами, многоуровневыми
таблицами без границ и нестандартными встроенными объектами остаётся
эвристическим. XLSX **не вычисляет** Excel-формулы, а сохраняет их.
Старый `.doc`, `.xls`, изображения без PDF-обёртки и `.odt` пока не поддерживаются.

## Что изменено в поиске и ответах

- Строки таблиц индексируются **вместе с названием столбцов**; исходная
  Markdown-таблица сохраняется в DocStore для проверки.
- Из многих тысяч таблиц можно получить конкретный артикул, цену, диапазон
  значений или формулу с её местом в исходном документе.
- Файлы `region1/manual.pdf` и `region2/manual.pdf` не смешивают ссылки и чанки.
- Встроенные формулы Word и выражения Excel сохраняются без попыток
  «додумать» вычисленный результат.
- Гибридный поиск: FTS5/BM25 + опциональный FAISS; reranker можно включить
  для лучшей сортировки найденного, **после проверки на своём корпусе**.
- Общий промпт не имеет правил, привязанных к КОИБ; он требует оснований и
  реальных ссылок. Неподтверждённые цифры и фальшивые цитаты помечаются
  как требующие проверки.
- Семантический кэш отделяет версии индексированных документов.

## Быстрый запуск: только SQLite, без скачивания моделей

Подходит для больших коллекций, когда вначале важна полная структурная
индексация, а семантические эмбеддинги планируются отдельно.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-indexer-lexical.txt
# Ubuntu/Debian: sudo apt-get install tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng
cp .env.indexer.example .env
# в .env добавьте KOIB_BUILD_VECTORS=false и RAG_DOMAIN=general
# поместите папки с документами в data/docs/
python index_app.py ingest --rebuild
python index_app.py verify
python index_app.py pack --out index_bundle.zip
```

Затем на сервере в отдельной сборке:

```bash
pip install -r requirements-server-lexical.txt
cp .env.server.example .env
# задайте KOIB_API_KEY и параметры LLM_PROVIDER
python -m tools.index_transfer unpack --archive index_bundle.zip --output-dir ./output
python serve_app.py --serve
# GET /ready → ready/degraded; POST /query требует X-API-Key
```

В этом режиме **обновления / удаления отдельных документов** поддерживаются
без пересборки всего индекса: повторите `python index_app.py ingest`.
Первый запуск без `--rebuild` создаст новый индекс, если его нет.

## Гибридный поиск с векторами

```bash
pip install -r requirements-indexer.txt
# в .env: KOIB_BUILD_VECTORS=true
# LOCAL_EMBEDDING_MODEL должна совпадать на индексаторе и сервере
python index_app.py ingest --rebuild
python index_app.py pack --out index_bundle.zip
```

На сервере установите `requirements-torch-cpu.txt` и
`requirements-server.txt`. FAISS загружает сериализованный LangChain pickle,
поэтому требуется **явное** `KOIB_TRUST_FAISS_PICKLE=true` **только для
архивов, собранных и проверенных вами**. При изменении или удалении исходных
документов в гибридном режиме выполните **полную переиндексацию**: безопасное
обновление существующих векторов по одному документу пока не реализовано.

Векторная модель `multilingual-e5-small` остаётся совместимым значением по
умолчанию; для исследования качества можно использовать более крупную модель
и multilingual-reranker, но **только с пересборкой векторов и измерением метрик**.

## Как измерять качество на своих документах

Создайте `cases.jsonl`, одна строка — один проверяемый вопрос:

```json
{"query":"Какова масса узла XZ-120?", "source":"catalog/equipment.xlsx", "contains":"45 кг"}
{"query":"Какая формула используется в расчёте?", "source":"engineering/formulas.docx", "contains":"(a)/(b)"}
```

Оцените Recall@5 и MRR@5, выставив порог качества для CI:

```bash
python -m tools.quality_gate --output-dir ./output --cases cases.jsonl \
  --k 5 --min-recall 0.85 --out ./quality-results.json
```

Бенчмарк **измеряет найденные фрагменты**, не достоверность генерации LLM.
Для реальной оценки качества ответов нужно также разметить факты, ссылки,
вычисления, конфликты документов и отсутствие ответа.

## Тесты и сборки

```bash
pip install -r requirements-test.txt
python -m pytest -q
python -m compileall -q api src tools
python make_apps.py --zip
```

В `dist/` окажутся раздельные сборки `koib-indexer` и `koib-server`.
Docker поддерживает `SEARCH_PROFILE=lexical` (без Torch) или `hybrid`;
жёсткий лимит оперативной памяти 2 ГБ не установлен.

**Рекомендуемая процедура перед production:** протестируйте реальные PDF-сканы
на своих языках, проверяйте распознанные таблицы/формулы на выборке,
создайте gold-набор вопросов и включайте reranker/большую embedding-модель
только после объективного улучшения Recall@k и качества ответов.
Подробности — `docs/UNIVERSAL_CORPUS.md` и `QUALITY_REPORT.md`.
