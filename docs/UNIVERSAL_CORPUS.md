# Проектирование большой разнородной базы знаний

## Точки расширения

1. `src/parsing.py` — PDF/DOCX/CSV/TXT и единая модель `DocumentElement`.
2. `src/universal_parsing.py` — XLSX, HTML, PPTX, JSON/JSONL и будущие адаптеры.
3. `src/scanned_tables.py` — консервативная табличная OCR по линиям сетки.
4. `src/math_intelligence.py` — линеаризация Office Math; сырой OMML хранится в метаданных.
5. `src/table_intelligence.py` — Markdown-сетка, значимые пары «столбец: значение» и окна по строкам.
6. `src/chunking.py` — отдельные чанки строк таблиц, формул, рисунков и текста.
7. `src/indexing.py` — независимый SQLite FTS5 / DocStore + необязательный FAISS.
8. `src/retrieval.py` — гибридный поиск и восстановление полного контекста.
9. `tools/quality_gate.py` — регрессионный бенчмарк на фактах исходного корпуса.

## Протокол импорта

`data/docs/` может содержать много уровней каталогов. Относительный путь
становится source ID и сохраняется в цитатах. Для Excel `page` — номер строки,
для PPTX — номер слайда, для DOCX — номер порядкового блока; это **не**
печатная страница. Дополнительные поля ответа `sources`:
`sheet`, `row_start`, `row_end`, `slide`, `table_id`, `chunk_id`.

Расширение парсера должно сохранять: точный текст, место, источник, тип,
структурные отношения и достоверность OCR (если эвристика). Избегайте
выдуманных табличных ячеек и «предположительно правильных» символов формул.

## Размеры и надёжность

- Для больших коллекций начинайте с `KOIB_BUILD_VECTORS=false`: SQLite
  индексирует и ищет по тексту без нейросети, поддерживает точечные изменения
  и удаление файлов. Добавление документов распараллелено с ограниченной
  очередью ожидающих заданий; длинные TXT и CSV читаются частями.
- Индексаторы могут потреблять больше памяти при больших **единичных**
  PDF/DOCX/JSON/XLSX и при FAISS. В частности, один PDF всё ещё парсится
  целиком по страницам, а чанки сохраняются в памяти до обработки документа.
- Векторный FAISS индекс этой версии остаётся локальным на одном хосте.
  Обновление/удаление источника в векторном режиме требует rebuild; миллионные
  распределённые индексы и многопользовательский ingestion-оркестратор не
  реализованы. При необходимости горизонтального масштабирования добавьте
  Postgres/pgvector или Qdrant, job queue, централизованный storage и ACL.
- Семантический кэш выключен по умолчанию; при включении ключи привязаны к
  отпечатку файлов индекса. Это предотвращает возврат старого ответа после
  обычной замены индекса, но не обеспечивает транзакционный rollout нового
  индекса на несколько серверов. Обновляйте index bundle атомарно.
- Архив индекса создаётся после checkpoint WAL. Перед передачей проверьте
  архив с SHA-256-манифестом и `index_app.py verify`.

## Таблицы и формулы

- XLSX хранит формулы как `=SUM(...)`, `=B2*C2`; openpyxl не вычисляет их.
  Для вычислений используйте авторизованный вычислительный сервис и отмечайте
  версии книги / датасета. Адрес ячейки сохраняется в метаданных.
- Word OMML — доступна структура основных арифметических объектов; сложные
  матрицы, интегралы, специальные операторы и рукописная математика требуют
  внешнего структурного математического OCR. Не обещайте точность без эталона.
- PDF с извлечёнными таблицами: сохранение ячеек возможно, но merged cells,
  повёрнутые таблицы и многоуровневые шапки требуют ручного QA.
- OCR таблиц-сканов: распознаются прямоугольные линейные сетки. Таблицы без
  границ остаются OCR-текстом. В метаданных помечается `confidence=heuristic`.
- Исходная табличная сетка остаётся доступна для проверки фактов. Для поиска
  в ней используется отдельная текстовая формулировка каждой группы строк.

## Как улучшать качество с измерениями

1. Отберите минимум 100–300 типичных вопросов по **вашим** документам:
   табличные факты, номерной поиск, формулы, сканы, факты из нескольких файлов,
   противоречивые версии, вопросы с отсутствующим ответом.
2. Для каждой записи укажите проверенный `source`, `contains` или оба; для
   генерации дополнительно эталонные факты, цитаты и допустимость вычисления.
3. Зафиксируйте Recall@5/MRR@5 на FTS5; затем включите FAISS и reranker
   и повторите те же вопросы. Сохраняйте CSV/JSON отчёты между изменениями.
4. Отдельно замерьте долю верно распознанных строк, ячеек и математических
   конструкций (cell exact match / symbol accuracy). Текущие pytest-тесты
   охватывают конкретные синтетические случаи, **не** являются валидированным
   OCR-бенчмарком ваших документов.
5. Настройте `LLM_PROVIDER`, проведите ручную/полуавтоматическую оценку
   фактичности, реальности цитат, полноты и уместности отказов. Код проверяет
   источник и явные числа эвристически; он не доказывает весь смысл ответа.

## Безопасность

Не включайте `KOIB_TRUST_FAISS_PICKLE=true` для неизвестных архивов.
Задавайте `KOIB_API_KEY`, ограничивайте сеть и права на каталог индекса,
проверяйте лицензии и персональные данные в документах. ACL по документам,
многопользовательская изоляция и PII-редакция **не реализованы**:
не используйте общий индекс с данными разной секретности без внешних средств
изоляции доступа. Удаление файла из индекса не гарантирует удаление копий
в резервных архивах и логах.
